# راه‌اندازی تحلیل رفتار در Frontend

## وضعیت فعلی

کد مرورگر و رابط رضایت‌گیری به `docs/index.html` وصل شده‌اند، اما جمع‌آوری داده در انتشار فعلی عمداً خاموش است:

- `docs/analytics-config.js` مقدار `apiBase` را خالی نگه می‌دارد.
- تا وقتی URL سرویس SaaS تنظیم نشده باشد، هیچ درخواست تحلیل رفتاری ارسال نمی‌شود و دکمهٔ موافقت غیرفعال است.
- بعد از تنظیم API، کاربر باید نشست احراز هویت‌شده داشته باشد و رضایت را در سرور ثبت کند. کاربر ناشناس یا کاربری که رضایت نداده است هرگز ردیابی نمی‌شود.
- صفحهٔ حساب فعلی در GitHub Pages هنوز رابط محلی/placeholder است؛ بنابراین ورود SaaS از همین صفحه هنوز در دسترس نیست. تا اتصال ورود، نشست و سرور واقعی، جمع‌آوری فردی فعال نخواهد شد.

## تنظیمات انتشار

پس از آماده شدن سرور دائمی SaaS و دامنهٔ نهایی، مقدار زیر را در `docs/analytics-config.js` تنظیم کنید:

```js
window.TLOOMBERG_ANALYTICS_CONFIG = Object.freeze({
  apiBase: "https://api.example.com",
  consentVersion: "v1",
  flushIntervalMs: 10000,
  activeTickMs: 15000,
  maxQueueSize: 200
});
```

`api.example.com` فقط نمونه است و نباید بدون سرور واقعی جایگزین شود. هیچ کلید، رمز، توکن یا credential نباید در فایل عمومی GitHub Pages قرار بگیرد.

## دامنه، نشست و CORS

API فعلی از کوکی امن `tloomberg_session` با `SameSite=Lax` استفاده می‌کند. برای اینکه درخواست‌های cross-origin مرورگر بتوانند این کوکی را همراه بفرستند، دامنهٔ سایت و API باید در یک site باشند؛ برای مثال سایت `https://tloomberg.example` و API `https://api.tloomberg.example`. با آدرس پیش‌فرض `itmahdik.github.io` و API روی دامنهٔ مستقل، این کوکی به‌طور قابل اتکا ارسال نمی‌شود. راهکار مناسب، تعیین دامنهٔ سفارشی برای GitHub Pages و API هم‌سایت است یا reverse proxy هم‌مبدأ روی میزبان واقعی.

در سرور SaaS نیز:
- `SAAS_ALLOWED_ORIGINS` باید دقیقاً origin منتشرشدهٔ سایت را داشته باشد (بدون wildcard).
- کوکی امن و HTTPS باید فعال باشند.
- `SAAS_TRUSTED_HOSTS` باید hostnameهای واقعی API را allow-list کند.
- نشست احراز هویت باید با همان API در دسترس سایت باشد.

## چه داده‌هایی جمع می‌شوند؟

فقط بعد از پاسخ موفق سرور به `PUT /analytics/consent` با `product_analytics=true`:

- `page_view` و `navigation` برای مسیرهای داخلی سایت؛ نماد مشاهده‌شده می‌تواند در مسیر صفحهٔ نماد بیاید.
- `click` فقط با شناسهٔ ثابت رابط مانند `nav-market` و نقش عنصر؛ متن دکمه یا لینک خوانده نمی‌شود.
- `scroll` در آستانه‌های ۲۵، ۵۰، ۷۵ و ۱۰۰ درصد.
- `active_time` در بازه‌های ۱۵ ثانیه‌ای، فقط وقتی صفحه visible و پنجره فعال است.

شناسهٔ کاربر و نشست از سمت سرور استخراج می‌شوند؛ مرورگر حق تعیین آن‌ها را ندارد. شناسهٔ سرمایه‌گذار در مسیر ثبت نمی‌شود. آدرس query/fragment، محتوای تایپ‌شده، مقادیر فرم، password، OTP، داده‌های پرداخت، اطلاعات بانکی، IP و user-agent ارسال نمی‌شوند.

## رضایت و لغو آن

- پیش‌فرض سرور `product_analytics=false` است.
- با قبول کاربر، رضایت در API ذخیره می‌شود و بعد از تأیید سرور، رویدادها فرستاده می‌شوند.
- با رد یا لغو رضایت، صف محلی فوراً پاک و ثبت رویداد متوقف می‌شود؛ API نیز تلاش می‌کند رضایت را لغو کند.
- اگر API پیکربندی نشده یا کاربر وارد نشده باشد، ثبت رویداد غیرفعال می‌ماند.
- تنظیمات «حریم خصوصی» همیشه از گوشهٔ پایین صفحه قابل بازکردن است.

## بررسی محلی

روی محیطی که Node.js دارد:

```bash
node --check docs/analytics-config.js
node --check docs/analytics.js
node --test tests/pages/analytics.test.cjs
```

GitHub Actions همین تست‌ها را به همراه تست‌های Python و PostgreSQL اجرا می‌کند.
